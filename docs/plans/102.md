## Context

Sub-issue A of #88 (https://github.com/nathpaiva/pompom-time/issues/88), the riskiest issue
in the redesign. #88 was split into three sub-issues after a brainstorming session with Nath,
to keep each PR reviewable on its own:

- **#102 (this branch)** — static layout, real data, no animation.
- **#103** — `usePulse` rewritten as a discrete phase state machine (no smooth motion yet).
- **#104** — continuous rAF-driven animation (SVG ring, RGB color lerp, `translateY` lift).

This plan covers #102 only.

## Goal

Replace the current placeholder `WorkoutTime.tsx` (a plain Chakra box with CSS-keyframe
animation) with the new design's static layout, reading real workout data from
`useGetWorkoutById`. No timers drive smooth motion in this issue — clicking through phases
(if exercised at all here) just swaps static style/text values. `usePulse` keeps its current
interval-based shape; it is not touched until #103.

## Layout to build (from the #88 issue spec)

- Header: back arrow + workout name (Quicksand 700 17px) + "Set X of Y" (`pompom.textMuted`
  `#8D8096`, 12px).
- Variety preview switcher: 4 small pills, active pill filled with the variety's color
  (`varietyColorMap`), the other 3 outlined.
- Breathing circle: 210px circle centered inside a 240px ring area.
- Inside the circle: uppercase phase label (Quicksand 700 11px, white 80% opacity) + status
  text (Quicksand 700 38px, white).
- Sub-line under the circle: variety motion description (`pompom.textMuted`, 13px). Draft
  copy, approved by Nath:
  - Pulse: "Quick squeeze and release, light and fast."
  - Intensity: "Deep squeeze that gets stronger each rep."
  - Resistance: "Hold the squeeze, then let go slow."
  - Strength: "Squeeze up and lift, then lower back down."
- Rep dots row: one dot per rep (`squeeze` count), filled with the variety color as reps
  complete — same underlying data usePulse already exposes today (`pulseInterval`, `counter`).
- Controls: "Start workout" / "Pause" / "Done" primary button (`pompom.primary` `#655D8A`) +
  "Reset" outline button, 2-column grid.

## Explicitly out of scope for #102

- No SVG progress ring (`#104`).
- No RGB color interpolation between relaxed/variety/rest colors (`#104`).
- No `translateY` lift for Strength (`#104`).
- No new state machine phases, no per-variety timing table (`#103`). `usePulse`'s public
  shape (`isPulsing`, `isCountingDown`, `isResting`, `counter`, `pulseInterval`,
  `restingInterval`, `countingDownInterval`, `handleStartStopPulse`) stays as-is; the new
  layout just re-skins around the existing values.

## Approach

1. **New sub-components** under `WorkoutTime/components/`, one folder each (matching the
   project's feature-folder convention):
   - `VarietySwitcher/` — 4 pills, active styled via `varietyColorMap[data.variety]`.
   - `BreathingCircle/` — the 210px circle, phase label + status text, sub-line. Takes the
     current discrete display values as props (no internal timing logic).
   - `RepDots/` — replaces the inline `.map` block already in `WorkoutTime.tsx` today, same
     data shape (`squeeze`, `pulseInterval`, `isPulsing`), just restyled to match the design
     (filled dot = variety color, not `pink`).
   - `WorkoutControls/` — the 2-button grid, restyled colors/labels ("Start workout" /
     "Pause" / "Done" / "Reset"). "Pause"/"Done" label swap is UI-only in this issue — actual
     pause-vs-reset *behavior* differs starting in #103; for now both map to the existing
     `handleStartStopPulse` toggle, same as today.
   - Follows the existing `<Component>/<Component>.tsx` + `index.ts` barrel shape used
     throughout `Workout/components/` and `AddWorkout/components/`.
2. **`WorkoutTime.tsx`** becomes a thin layout shell composing the above, replacing the
   current ad-hoc Chakra tree. Keeps calling `useGetWorkoutById` + `usePulse` exactly as
   today — no hook changes.
3. **Status text logic** (what the big 38px text shows: countdown digit / "rep/total" / hold
   seconds / rest seconds) moves from the inline ternary in today's `WorkoutTime.tsx` into
   `BreathingCircle`, unchanged in behavior — just relocated so the parent stays a thin
   composition layer.
4. **Remove** `animationTime.ts` and its `TWorkoutAnimation` type (`WorkoutTime/types.ts`) —
   the CSS-keyframe animation they drove is fully replaced by the new layout (and, later,
   #104's rAF animation). No replacement file needed in #102 since no animation exists yet.
5. **Back arrow** navigation: check `router.tsx` for the existing "My workouts" list route
   and wire the back arrow to `useNavigate` back to it, matching the pattern already used
   elsewhere (e.g. `AddWorkout`'s own back navigation, if present — confirm during
   implementation).
